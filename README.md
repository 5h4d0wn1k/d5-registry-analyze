# D5 — Registry Analyzer

Windows registry hive parser and timeline generator for digital forensics.

## Overview

This project parses Windows registry hive files (e.g., `NTUSER.DAT`, `SYSTEM`, `SOFTWARE`) and extracts:
- Key enumeration and hierarchy
- Value name/type/data decoding
- Last-write timestamps for timeline analysis
- Hive header metadata and version
- **Autostart / persistence detection** (Run and RunOnce values)

## Features

- **Hive parsing**: regf header, cells, nk/vk blocks
- **Key enumeration**: nested key tree with values
- **Value decoding**: REG_SZ, REG_DWORD, REG_QWORD, REG_BINARY, REG_MULTI_SZ
- **Autostart / persistence**: extracts command strings in `Run` / `RunOnce` keys
- **Timeline**: sorts key last-write events chronologically
- **Subkey lists**: lf/lh/ri index handling

## Usage

```bash
python3 cli.py --input NTUSER.DAT --output report.json
python3 cli.py --demo
```

Run without arguments for help. All JSON/Markdown reports land in the git-ignored `reports/` directory.

## Tests

```bash
python3 -m unittest discover -s tests
```

The engine (`firmware/registry.py`) is stdlib-only (`struct`, `os`, `datetime`, `json`).
A structurally-faithful synthetic hive fixture (`tests/fixtures/test_hive.regf`) is
generated by `tests/generate_fixtures.py`, which implements the on-disk REGF_NI layout
byte-for-byte (regf header, nk, vk, lf lists, UTF-16LE names and REG_SZ data).

## Live Lab Test Plan

1. Clone a real captured hive (e.g. `NTUSER.DAT`) into `tests/fixtures/` and run `python3 cli.py -i tests/fixtures/NTUSER.DAT -o reports/live.json`.
2. Verify the parser lists the known user keys (`Software`, `Environment`, `Run`) with correct value counts.
3. Verify `Software\Microsoft\Windows\CurrentVersion\Run` / `RunOnce` value command strings appear in the `autostart` section.
4. Cross-check a few decoded REG_DWORD / REG_SZ values against a reference viewer (e.g. `regedit` or `python-registry`).
5. Confirm last-write timestamps match the displayed values within the hive.
